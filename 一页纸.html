② 当前痛点
⚡
突发性强，时间成本高 问题随时出现，无预警机制；一旦出现会大量占用产品/研发时间，打断正常工作节奏
🔭
排查范围广，定位难 需要关注维度多（规则/标签/模版/链路/过滤...），无法快速收敛到具体问题所在层级
🧠
强依赖个人经验，缺乏沉淀 排查逻辑靠老手脑子里的经验，没有系统性知识积累，每次都从零开始
🏝️
数据分散，信息孤岛 adata / 千寻 / SDK 日志各平台独立，需要手动跨系统拼凑信息，效率极低
📦
业务黑盒，链路不透明 广告请求→过滤→出广告的完整链路不可视，出了问题不知道卡在哪个环节
🔄
流转成本高，找人效率低 自查后仍需找对应研发值班同学；找人、对齐、等回复的过程本身就是时间损耗
对应 5/19 共识痛点 本模块主攻「技术支持沉淀缺失」「Case 排查难」两大方向：知识库自更新机制解决经验口传问题；多源数据聚合 + AI 归因打通信息孤岛。效果归因难 / 规则配置耗精力由对应模块主攻，本模块侧面支撑。
③ 模块定位 · 解决什么问题
✅ 模块做
🔍
结构化信息收集 引导提报人规范填写媒体ID/广告位ID/回包/截图，减少来回拉信息
📡
多源数据拉通 adata 业务数据 + 千寻规则/标签 + SDK 日志三源聚合，一屏呈现
🤖
AI 辅助归因 基于历史 case 知识库 + 当前数据，输出结构化排查路径
📚
经验自动沉淀 解决方案归档 → 知识库自更新 → Agent 学习积累 → 下次更快

⑥ 知识库自更新机制
💡 最终目标：成为一个越用越聪明的 AI 排查员工
1
用户描述问题 → Agent 解析结构化信息

对话框自然语言输入 → Knot Agent 自动提取：媒体ID / 广告位ID / 问题类型 / 场景 / 严重程度

Knot AgentPrompt 工程
2
自动追加一行到知识库表格

解析结果 → 自动写入腾讯文档知识库表格，新行标红（解决方案字段待填写）

腾讯文档 MCP
3
平台点击推送 → 企微 Agent 通知值班研发

在问题排查平台点击「推送研发」→ 企微侧问题排查 Agent 自动向当周值班研发发送消息，消息内包含问题描述摘要和解决方案填写入口；研发直接在企微 Agent 对话框内回复解决方案，Agent 自动将内容写入知识库表格对应行，无需研发手动打开文档

企微 Agent问题排查平台腾讯文档 MCP
4
Agent 定时巡检 → 学习新解法

Knot 定时任务定期读取知识库表格，读取已填写的解决方案行，更新 Agent 知识库，下次相似问题自动召回

Knot Cron知识库检索
5
闭环通知 · 主页更新 case 处置结果

问题处置完成后，通知提报人处置结果；主页 case 状态同步更新为「已处置」，方便追踪整体进展

⑦ 协同视角清单 · 基座接口回应
1. AI 路由关键词清单 必要
不想出样式 模板异常 case 媒体反馈 出不了 无法展示 为什么没有 无关闭按钮 无倒计时
触发示例 用户输入「媒体101030735429激励视频出不了广告」→ 路由到问题排查模块，自动带入媒体ID参数
2. Skills 提报清单 必要
Skill 名称用途关键词类型
模版问题快速排查 输入媒体ID+截图，自动定位模版ID并拉取千寻标签 模版/出不了/截图 B类
广告回包解析 粘贴回包JSON，自动解析关键字段并高亮异常 回包/JSON/解析 B类
研发值班推送 一键推送问题描述给当周值班研发 推送/值班/派单 A类
⑧ 待对齐事项 · 需研发协同
P0
多元数据打通：adata / 千寻 / TAPD 接入方式
adata 业务数据 API 字段口径、千寻规则 API 调用方式（能否查询规则命中/nomatch 原因）、TAPD 缺陷单自动创建接口 —— 以上均需研发侧确认后才能接入真实数据
P0
广告回包格式与字段定义
广告汇报的 JSON 结构有哪些关键字段？哪些字段可用于异常诊断？当前直接转研发处理，需形成结构化文档供 AI 解析
P0
SDK 日志检索接口
SDK 日志是否可通过媒体ID / 广告位ID 查询？历史排查问题是否有存档可复用？
P1
企微 Agent 联动推送 · 研发填写解决方案入口
问题排查完成后，Knot 推送消息给对应研发值班同学，并附上解决方案填写入口（企微 Agent 对话框）；研发在对话框内回复解决方案后，由 Agent 自动写入知识库表格，无需研发手动打开腾讯文档。需确认：① 企微侧 Agent 与问题排查模块的联动方式；② 研发接受在企微 Agent 对话框内填写的交互形式
P1
截图识别模版 ID 可行性
截图能否联动 iDOMO / 千寻预览图识别出模版 ID？目前靠人工判断，AI 识别可大幅提效
P1
研发值班排期同步
值班表如何与系统同步？推送时如何自动获取当周值班人？建议接入企微值班日历
P1
TAPD 缺陷单创建接口权限
问题归档时自动在 TAPD 创建 Bug 单，需确认 TAPD MCP 的项目权限及字段映射（复现步骤 / 解决方案 / 关联人）
P2
研发现有排查 Skills 融入
研发侧是否已有问题排查相关的 Skill / 脚本？如何复用而不是重复建设？
说明 以上均为「需研发协同确认」的卡点，当前 Demo 为 mock 数据展示流程。路演后根据反馈逐步对齐，并在决策档案沉淀结论。
